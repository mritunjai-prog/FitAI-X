Workout Hub — Zero Cards

Every container removed. No rounded surfaces, no borders, no glass boxes, no nesting. Content sits directly on the mesh gradient and hierarchy is carried purely by type scale, spacing, hairline rules and the gold accent — the way Apple's own Fitness, Health and Settings screens are built.

What "no cards" changed

  • Removed entirely — GlassCard, grouped list containers, tinted tiles, bordered stat boxes, the segmented pill track, circular nav button chrome and every borderRadius + borderWidth + backgroundColor surface.
  • Tabs — sliding gold underline on a hairline baseline instead of a pill inside a bordered track.
  • Nav buttons — bare 22px glyphs, no 40px circles.
  • Stats — columns divided by vertical hairlines, bounded by a top/bottom rule; no tiles.
  • AI coach — a 2.5px gradient rail plus type. No fill, no border, no radius.
  • Builder steppers — 2×2 hairline-divided grid; only the ± hit targets keep a shape, because they're controls.
  • Active — state shown by a full-bleed gradient wash that fades to transparent at 80%, so there's no visible edge; completed sets tint the whole row width.
  • History — continuous timeline rail through full-bleed entries separated by hairlines; no session cards.
  • Kept as shapes — buttons, chips, the ± steppers and the tick circle. Those are interactive controls, not containers, and flattening them would break affordance.

Review round 2 — three asks resolved

  • 1 · History filter is real. Tap Filter on the History tab. Four flattened rows (All time / Past week / Past month / PR sessions only) with live counts and a gold check on the active one. Selection actually narrows the dataset — PR shows 2 sessions, Past week shows 3 — and the summary columns + range label recompute. A fifth row toggles the empty state for preview.
  • 2 · Hold-to-end now matches its copy. Finish Workout is a genuine 1-second press-and-hold: a white progress sweep fills the button, the label switches to “Keep holding…”, and the hint reads “RELEASE TO CANCEL”. Releasing early aborts with no state change — an accidental tap can no longer end a live session. Completing the hold swaps the dock to a green “Session saved” confirmation plus a View in History action, and the header sub-status becomes “Session complete · saved”.
  • 3 · Empty state built. Flattened treatment — muted 52px dumbbell glyph at 30% opacity, title, two-line explainer, single gold CTA. Two distinct copies: true first-run (“No sessions yet”) vs. a filter returning nothing (“Nothing in this range”), which offers to widen the range instead of starting a workout.

Consistency decision — propagate to Dashboard & Profile

  • Recommendation: propagate both. 👍 The flattened nav glyphs and underline tabs should replace the circular glassInset buttons and pill nav app-wide, not stay Workout-only. Three screens sharing a header treatment while a fourth diverges reads as an unfinished migration, not an intentional accent — and the header is the most-seen element in the app.
  • Sequencing — ship Workout Hub first as the reference implementation, then port the header (glyph buttons + large title + underline tabs) to Dashboard and Profile as a follow-up. Do not ship all three simultaneously; you want one screen proving the pattern in real use first.
  • What does NOT propagate — Dashboard's bento grid is genuinely card-appropriate (independent, tappable, reorderable data tiles), and Profile's TiltCard hero earns its surface. Flatten the chrome (headers, tabs, buttons), keep those two content patterns.
  • Cost — roughly one file each. Header is self-contained in both; no data-layer changes.

Handoff notes for WorkoutScreen.tsx

  • Do not port the SVG helpers in this file. ringSVG, sparkline, bodyMap and the inline ICON_PATHS here exist only because the browser has no access to your RN components. Map back to the real primitives: rings → ActivityRings, bars → BarChart, sparklines → SplineChart, icons → the existing shared Icon/ICON_PATHS. Treating this HTML as literal code would create a fourth divergent chart implementation.
  • TiltCard extraction is now moot for this screen — almost nothing here uses a blurred panel. Skip it. GradientText is still worth sharing — the hero's gradient “Strength” and the AI Coach accent both need it.
  • Hold gesture → Pressable with onPressIn/onPressOut driving a useSharedValue width via withTiming(1, {duration:1000}), cancelled on onPressOut; fire completeSession in a runOnJS callback. Add Haptics.notificationAsync(Success) on completion.
  • Filter state is local UI state — filter fetchWorkoutHistory's result client-side, or pass a range param if the endpoint supports it.
  • Hairlines → StyleSheet.hairlineWidth, never 1, or they render heavy on 3x devices.
